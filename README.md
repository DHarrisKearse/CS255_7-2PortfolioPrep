# CS255 8-2 Journal: Portfolio Submission
# DriverPass System Analysis & Design Project

## Project Summary

The DriverPass project focused on designing a system for a driving education company. The client, DriverPass, wanted a web-based system that would allow customers to register for training packages, schedule driving lessons, take online courses, and complete practice tests. The system also needed to support administrative functions such as managing user accounts, tracking reservations, assigning drivers and vehicles, and generating reports. The goal was to create a system that improves customer success rates on driving exams while making the business more efficient.

---

## What I Did Well

One thing I did particularly well was translating the client’s needs into clear system components and diagrams. I was able to take the information from the interview and break it down into functional requirements, then represent those requirements visually using UML diagrams. My activity and sequence diagrams clearly show how the system operates step by step, and my class diagram reflects how the data is structured and connected. I also did a good job keeping the design organized and aligned with the client’s goals.

---

## What I Would Revise

If I could revise one part of my work, I would improve the clarity and visual layout of my UML diagrams. While they accurately represent the system, I would spend more time refining spacing, alignment, and readability to make them easier to understand at a glance. I would also simplify some flows to reduce visual clutter and make the diagrams more user-friendly for nontechnical stakeholders.

---

## Interpreting User Needs

I interpreted the user’s needs by carefully analyzing the interview transcript and identifying both functional and nonfunctional requirements. I focused on what the users needed to do, such as scheduling lessons, accessing training materials, and managing accounts, and then built those actions into the system design. Considering user needs is critical because the system is ultimately built for them. If the design does not align with how users actually interact with the system, it can lead to frustration, inefficiency, and poor adoption.

---

## Approach to Software Design

When designing software, I focus on breaking the system into smaller, manageable parts and understanding how each part interacts with the others. I start by identifying the users and their goals, then map out processes using diagrams like use case, activity, and sequence diagrams. In the future, I would continue using these techniques, along with iterative design and feedback, to improve system accuracy and usability. I would also place more emphasis on testing and validation early in the design process to catch potential issues before implementation.
